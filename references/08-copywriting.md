# Copywriting and Content Standards

## Headlines

- Headlines should say what the product does or what the user gets
- One idea per headline. Compound headlines dilute impact
- Avoid headline formulas: "The [adjective] way to [verb]" is a slop pattern
- Use statements, questions, and imperatives — never all one type

| Slop | Intentional |
|---|---|
| "Elevate Your Workflow" | "Build APIs in Half the Time" |
| "Unlock the Power of AI" | "Generate Marketing Copy from Bullet Points" |
| "The Smart Way to Manage Teams" | "See Every Project Status in One View" |

## Body Copy

- Use plain language. If a simpler word exists, use it
- One thought per paragraph. Dense blocks signal unedited AI output
- Active voice, not passive
- Write for scanning: front-load meaning, use short paragraphs

## CTAs and Buttons

- Use action verbs: "Start trial", "Read docs", "See pricing"
- Never use "Learn more" — it says nothing about what happens next
- One CTA per section, or one primary + one secondary maximum
- Secondary CTAs should not compete visually with primary

| Slop | Intentional |
|---|---|
| "Learn More" | "See How It Works" |
| "Submit" | "Send Message" |
| "Click Here" | "Download the Guide" |
| "Get Started" | "Start Free Trial — No Card Required" |

## Testimonials and Social Proof

- Use real names, real roles, real companies — or do not use testimonials
- Quote real words, not marketing-speak attributed to a person
- Include photos only if they are real photos of real people
- Star ratings require review counts and verifiable sources

## Error and Empty States

- Error copy should explain what happened and what to do next
- Empty states should guide the user toward action, not just say "Nothing here"
- Loading copy should set expectations: "Analyzing your file..." not "Loading..."

| State | Slop | Intentional |
|---|---|---|
| Error | "An error occurred" | "We couldn't save your file. Check your connection and try again." |
| Empty | "No items found" | "You haven't created any projects yet. Start with a template." |
| Loading | "Loading..." | "Analyzing your document... This takes about 30 seconds." |

## Microcopy

- Labels should be scannable: "Save changes" not "Would you like to save your changes?"
- Confirm destructive actions: "Delete project" not just "Are you sure?"
- Success messages should be specific: "Project saved" not "Success!"
- Help text guides; it does not apologize

## Feature Descriptions

- Describe what the user CAN DO, not what the product IS
- Self-focused: "Our platform uses AI to optimize workflows"
- User-focused: "Finish your weekly reports in 10 minutes"

## Copy Bans

| Banned Pattern | Why | Replacement Strategy |
|---|---|---|
| "Elevate your workflow" / "Unlock the power of" / "Seamlessly" | Empty marketing fluff | Say what the product does in plain language |
| "Revolutionary" / "Game-changing" / "World-class" without evidence | Unsupported claims | Use specific metrics or remove the claim |
| "AI-powered" as a feature description | Says nothing about what it does | Describe the outcome, not the technology |
| Fake testimonials with generic names | Deceptive, damages trust | Use real quotes from real users, or remove |
| Placeholder text in shipped UI ("Lorem ipsum") | Unfinished work | Write real copy or use a loading state |
| "Learn more" as a CTA | Vague, low commitment | Use action verbs: "Read the docs", "See pricing", "Start building" |
| Heading + body + button in every section | Mechanical repetition | Vary section structures: quote-forward, stat-forward, image-forward |
| All headings are questions | Predictable pattern | Mix statements, questions, and imperatives |
| Feature lists that describe what the product *is* | Self-focused | Describe what the user *can do* with it |
| Release notes in passive voice | Distant, unengaging | Use active voice: "We fixed" not "Fixed was" |
